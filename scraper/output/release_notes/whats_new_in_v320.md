# What's New in V3.2.0

- [](/_docs/)- Release Notes- What's New in V3.2.0Export PDFOn this page# What's New in V3.2.0
**Release Date: April 24, 2026**

### Browser-based Pentests[​](#browser-based-pentests)
Adds support for browser-based pentesting, enabling teams to assess AI applications that are accessed and exercised through the browser. This expands testing coverage beyond direct API and endpoint interactions.

### Multi-modal Guardrails[​](#multi-modal-guardrails)
Introduces multi-modal guardrails to extend runtime protection beyond text-only interactions. This allows guardrails to evaluate and enforce policy across additional content types handled by supported AI applications.

### AWS Assumed Role Authentication in the Gateway[​](#aws-assumed-role-authentication-in-the-gateway)
Adds support for AWS Assumed Role authentication in the Gateway. This enables customers to route requests through the Gateway while using AWS role assumption for secure downstream access, improving support for Bedrock and other AWS-based integrations.

### Pentest Strategies[​](#pentest-strategies)
Introduces Pentest Strategies to improve how attack approaches are organized and executed during AI red team assessments. This creates a more structured foundation for test coverage and makes it easier to expand and compare different attack methods over time.

### AI Investigation Anomaly Detectors[​](#ai-investigation-anomaly-detectors)
Adds anomaly detectors in AI Investigation to help identify unusual behavior patterns and outliers in runtime activity. These detectors improve visibility into potentially risky or unexpected changes in AI system behavior.

### Bedrock AgentCore Discovery[​](#bedrock-agentcore-discovery)
Adds discovery support for AWS Bedrock AgentCore. Customers can now identify and inventory Bedrock AgentCore resources as part of their broader AI asset discovery workflows.

### Runtime Policy Automations[​](#runtime-policy-automations)
Introduces Runtime Policy Automations to enable automated responses tied to runtime policy outcomes. This helps teams operationalize runtime detections more efficiently and reduce manual follow-up for common actions.

### Gateway Selective Logging[​](#gateway-selective-logging)
Adds Gateway Selective Logging so customers can control what Atlas stores for each prompt source. Customers can now configure Prompt Logging and Operational Metrics Logging independently, including options to store all content, store content only when actions or issues occur, or store no prompt content at all.
