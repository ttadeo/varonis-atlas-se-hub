# Atlas Guardrail Types Reference

## Prompt Protection

Gateway-level rules that analyze and enforce security policies on prompts and responses in real time. These rules detect and block a wide range of threats including prompt injection, jailbreak attempts, data leakage, code injection, and content policy violations.

---

### AI-Generated Content Detection

Determines the likelihood that a given text was generated by an AI model or written by a human, using linguistic and stylistic analysis. A minimum text length is required for evaluation, as shorter samples do not provide enough information for confident detection.

**Background:** As AI-generated content becomes increasingly prevalent, organizations need to distinguish between human and machine-authored text. This is critical for maintaining trust in communications, detecting automated influence campaigns, and ensuring compliance with disclosure requirements for AI-generated content.

---

### Banned Substrings

**OWASP:** LLM05:2025

Scans input or output text for the presence of any prohibited substrings specified in a user-provided list, using direct string matching to ensure exact detection.

**Background:** Organizations often need to enforce strict content policies that prohibit specific terms, phrases, or patterns. This rule provides a simple but effective mechanism for blocking known-bad content, including competitor names, internal project codenames, or specific harmful phrases.

---

### Code Injection and Generation Prevention

**OWASP:** LLM05:2025 | LLM01:2025 | LLM02:2025
**MITRE ATLAS:** AML.T0073 | AML.T0051.000 | AML.T0057

Detects the presence of code within a given text or image and evaluates it against a user-defined list of allowed and forbidden programming languages.

**Background:** Attackers might attempt to inject malicious code into software applications to alter or manipulate data. This code is often crafted to install malware or cause harm if executed. They may also conceal code within other text or spread it across multiple prompts to evade detection.

---

### Code Leakage Prevention

**OWASP:** LLM02:2025 | LLM01:2025
**MITRE ATLAS:** AML.T0074 | AML.T0057 | AML.T0051.000

Detects the presence of code within a given text or image and evaluates it against a user-defined list of allowed and forbidden programming languages.

**Background:** Prevents leakage of sensitive proprietary code to the LLM in prompt inputs. Organizations using AI coding assistants must ensure that confidential source code, algorithms, or trade secrets are not inadvertently exposed through prompts.

---

### Content Types

**OWASP:** LLM01:2025
**MITRE ATLAS:** AML.T0070 | AML.T0051.001

Analyzes the types of content included in a request to an LLM — such as text, image, audio, or video — and triggers if any disallowed content types are detected.

**Background:** Multimodal AI systems accept various input types, each carrying different risk profiles. Restricting content types helps reduce the attack surface by preventing exploitation through less-monitored modalities such as images or audio that may bypass text-based safety filters.

---

### Detect Languages

**OWASP:** LLM01:2025
**MITRE ATLAS:** AML.T0051.000 | AML.T0072 | AML.T0066

Identifies the language of the provided text and compares it against a user-defined list of allowed and forbidden languages. Triggers when disallowed languages are detected to enforce language-specific usage policies.

**Background:** Phishing emails or social engineering attacks often exploit language differences. Identifying the prompt language can help detect phishing attempts that use languages not commonly used within an organization.

---

### Detect Malicious URL

**OWASP:** LLM01:2025
**MITRE ATLAS:** AML.T0051.001 | AML.T0059

Identifies URLs within a given text and evaluates them against a set of predefined suspicious patterns and user-specified keywords. Triggers when a URL matches indicators commonly associated with malicious or unsafe content.

**Background:** A malicious URL is a link created with the purpose of promoting scams, attacks, and frauds. When clicked on, malicious URLs can download ransomware, lead to phishing or spearphishing emails, or cause other forms of cybercrime.

---

### Detect Sexual Content

**OWASP:** LLM05:2025
**MITRE ATLAS:** AML.T0065 | AML.T0066

Detects the presence of any form of sexual content in text, including explicit language, descriptions, or references, to prevent inappropriate or adult material from being processed or generated.

**Background:** Robust filtering of sexual content is essential for compliance with content policies and maintaining appropriate user experiences, particularly in enterprise and customer-facing applications.

---

### Detect Topics

**OWASP:** LLM05:2025
**MITRE ATLAS:** AML.T0066

Identifies whether the text discusses any forbidden topics, based on a predefined list or custom topics provided by the customer. This rule operates in alert and log-only mode, enabling monitoring without blocking the request.

---

### Function Call

**OWASP:** LLM05:2025
**MITRE ATLAS:** AML.T0053

Prevents function call argument injections and other unsafe code patterns in model outputs. Validates function calls, detects argument manipulation, and flags potential homograph or binary string exploits to ensure secure and predictable function execution.

**Background:** In cybersecurity, safeguarding against issues related to function calling focuses on protecting software from vulnerabilities and attacks that exploit how functions are executed.

---

### Grounding

**OWASP:** LLM01:2025 | LLM05:2025
**MITRE ATLAS:** AML.T0051 | AML.T0054 | AML.T0066

Evaluates model outputs against the system prompt and defined AI use case to ensure responses remain aligned with the intended purpose. Designed as a second line of defense to detect and mitigate successful prompt injections or other manipulations that cause the system to stray off-topic.

**Background:** Even with robust input-side protections, some prompt injections may succeed. Grounding provides output-side validation by verifying that the model's response stays within the boundaries of its defined role, catching cases where the system has been steered away from its intended behavior.

---

### PII Detection

**OWASP:** LLM02:2025
**MITRE ATLAS:** AML.T0057 | AML.T0058 | AML.T0060

Detects the presence of personally identifiable information (PII) within text. Compares any detected PII types against a user-defined list of forbidden fragments.

**Background:** The PII policy is established to safeguard sensitive data by identifying and blocking the exposure of Personally Identifiable Information during user interactions. Its main purpose is to maintain the privacy and security of user information by detecting and handling PII appropriately.

---

### Prevent Encoded Attacks

**OWASP:** LLM01:2025 | LLM05:2025
**MITRE ATLAS:** AML.T0051 | AML.T0072

Detects hidden or encoded text within prompts — such as Base64, Hex, Binary, Base32, HTML, or ASCII85 encodings — that may conceal malicious instructions or payloads. Uses pattern matching to identify sequences resembling encoded content and triggers when such encodings are detected.

**Background:** Attackers often use encodings to obfuscate their payloads or malicious instructions. By encoding content, they can hide the true nature of their input, making it harder for security systems to detect malicious intent.

---

### Prevent Jailbreak

**OWASP:** LLM01:2025
**MITRE ATLAS:** AML.T0051.000 | AML.T0054

Detects attempts to bypass or disable system safeguards by coercing the model into restricted behavior. Focuses on jailbreak-style manipulations such as role-playing, simulated system overrides, or requests to ignore established rules and policies.

**Background:** An attacker might try to input data that causes the LLM to bypass its safety controls and perform actions it normally wouldn't. This is often achieved through "role-playing" scenarios or by using complex and misleading prompts.

---

### Prevent Leakage

**OWASP:** LLM07:2025 | LLM02:2025
**MITRE ATLAS:** AML.T0055 | AML.T0056 | AML.T0057

Prevents exposure of confidential system information or secrets. On input, it detects explicit attempts to access or extract system instructions, hidden data, or internal configurations. On output, it monitors model responses for potential leakage of sensitive or proprietary information by comparing them against the system prompt as a reference.

**Background:** This refers to a scenario where an attacker manipulates the input prompts to extract sensitive or confidential information from the LLM, which the model should not reveal.

---

### Prevent Obfuscated Attacks

**OWASP:** LLM01:2025 | LLM05:2025
**MITRE ATLAS:** AML.T0051 | AML.T0072

Detects obfuscated or disguised malicious input intended to bypass security filters. Uses pattern recognition and configurable regex-based rules to identify suspicious encoding, character substitutions, or other evasion techniques designed to conceal harmful intent.

**Background:** Attackers may attempt to evade filters by replacing certain words or tokens that would trigger filters with synonyms or modifying them to include a typo.

---

### Prevent Prompt Injection

**OWASP:** LLM01:2025
**MITRE ATLAS:** AML.T0051 | AML.T0054

Detects attempts to inject malicious instructions into prompts that could override the system's intended behavior. Identifies patterns where users try to manipulate the model into ignoring its directives, revealing hidden data, or executing unintended actions.

**Background:** Prompt injection is one of the most critical vulnerabilities in LLM-based applications. An attacker crafts input that tricks the model into ignoring its system-level instructions and following attacker-controlled commands instead.

---

### Prevent Toxicity

**OWASP:** LLM05:2025
**MITRE ATLAS:** AML.T0065

Detects toxic or harmful language in model inputs and outputs, including hate speech, harassment, threats, and other forms of abusive or offensive content.

**Background:** Toxic content in AI interactions can damage brand reputation, create hostile user experiences, and expose organizations to legal liability.

---

### Profanity Check

**OWASP:** LLM05:2025
**MITRE ATLAS:** AML.T0065

Detects profanity or offensive language in model inputs and outputs using a library of profanities.

---

### Prohibit Topics

**OWASP:** LLM05:2025
**MITRE ATLAS:** AML.T0066

Identifies whether the text discusses any forbidden topics, based on a predefined list or custom topics provided by the customer. This rule enforces blocking when prohibited topics are detected, preventing the request from proceeding.

**Background:** Even with managed prompts, LLMs might generate outputs that address themes or subjects deemed sensitive, controversial, or beyond the intended scope of interactions.

---

### Remove Invisible Text

**OWASP:** LLM01:2025
**MITRE ATLAS:** AML.T0051.000 | AML.T0072

Detects and removes invisible or non-printable Unicode characters from prompts, such as zero-width spaces or other hidden symbols.

**Background:** Steganography using invisible text can be found in various online environments, including Amazon reviews, emails, websites, and even security logs. Attackers use characters that, while valid in Unicode, are not rendered by most fonts — hiding malicious instructions that the LLM sees and executes but humans cannot see.

---

### SQL Injection

**OWASP:** LLM01:2025 | LLM05:2025
**MITRE ATLAS:** AML.T0073 | AML.T0051.000 | AML.T0053

Detects SQL injection attempts. Identifies common attack patterns such as authentication bypass, UNION-based, time-based, and error-based payloads. Helps protect against malicious queries designed to access or manipulate underlying databases.

---

### XSS Protection

**OWASP:** LLM01:2025 | LLM05:2025
**MITRE ATLAS:** AML.T0073 | AML.T0051.000 | AML.T0053

Detects and prevents cross-site scripting (XSS) attacks in both input and output. Identifies and neutralizes malicious scripts, HTML tags, and payloads designed to execute unauthorized code in web contexts.

**Background:** This refers to a scenario where an attacker injects malicious scripts or HTML code into a prompt, aiming to execute it within the context of a web application or user interface that processes the model's output.

---

## Custom Policies

Flexible, user-defined rules that allow organizations to enforce custom evaluation logic beyond the built-in policy library.

### Custom Judge

Evaluates model input or output against user-defined criteria provided through a custom prompt. Enables flexible, use-case-specific enforcement by allowing organizations to define their own judgment logic for detecting undesired or policy-violating content.

**Background:** Custom Judge provides maximum flexibility for organizations with unique governance requirements. Rather than relying solely on rule-based detection, this policy uses a separate evaluator LLM to assess interactions against custom criteria, adapting to each organization's unique needs.

---

### Regex Pattern Match (Fail)

Triggers a fail action when text matches a specified regular expression pattern. Supports both full and partial (search) matching modes.

---

### Regex Pattern Match (Pass)

Passes validation only when the text matches a specified regular expression pattern. Supports both full and partial (search) matching modes.

---

## Model Robustness

Structural and operational controls that ensure model inputs and outputs conform to expected formats, sizes, and interaction patterns.

### Boolean Validation

Ensures the output of a prompt is a boolean value.

**Background:** Boolean content can sometimes be used in injection attacks where malicious actors try to manipulate the model's behavior by inserting logical conditions or payloads.

---

### Clip Token

Monitors the token length of text inputs and outputs, enforcing limits to maintain performance and safety. Supports configurable actions, including clipping text to a specified maximum length.

**Background:** The large size and complexity of LLMs make them prone to significant resource consumption, particularly when handling extended prompts. Malicious actors may take advantage of this by submitting excessively long inputs, intending to disrupt service or cause high computational expenses.

---

### JSON Validation

Ensures the output of a prompt is a valid JSON object.

**Background:** Ensuring that the JSON data used as input to or output from the model is properly formatted and does not contain malicious or unintended content that could exploit vulnerabilities.

---

### Message Count Control

Tracks the number of messages exchanged within a conversation thread. Enforces a configurable limit on total interactions, capping or ending the session once the defined threshold is reached.

**Background:** A common cybersecurity concern is prompt injection, where an attacker manipulates the input prompts to make the LLM behave in unintended ways. By monitoring the number of input prompt messages, it becomes easier to detect unusual patterns or sequences of prompts that might indicate an ongoing injection attack.

---

### Policy Message Rule

Automatically prepends or appends a predefined policy message to an LLM's response. Ensures that important disclaimers, compliance notices, or contextual guidance are consistently included in model outputs.

---

### String Validation

Validates text against a user-defined list of allowed strings. Ensures that only approved values or responses are accepted, enabling strict control over permissible outputs or inputs.

---

### Rate Limiting

Monitors and controls the frequency of requests across configurable identifiers — such as user IP, user email, or session ID — within a defined time period. Enforces customizable rate thresholds and can initiate quarantines when limits are exceeded.

**Background:** Rate limiting protects AI systems from abuse, denial-of-service attacks, and cost overruns by capping the volume of requests any single user or session can make. It also helps detect automated probing or scraping activity.

---

## AI Monitor Policies

Real-time evaluation and enforcement controls for AI system inputs and outputs. These policies assess the quality, safety, fairness, and appropriateness of LLM interactions.

### Sentiment

**Applies to:** Input, Output

Analyzes the sentiment of text and classifies it as positive, neutral, or negative. Enables downstream actions or monitoring based on emotional tone.

---

### Answer Relevance

**OWASP:** LLM01:2025 | **MITRE ATLAS:** AML.T0051 | AML.T0068
**Applies to:** Output

Evaluates whether the model's response is relevant to the defined purpose or use case of the AI system. Tags responses as relevant or irrelevant.

---

### Context Relevance

**OWASP:** LLM01:2025 | **MITRE ATLAS:** AML.T0051 | AML.T0068
**Applies to:** Input

Evaluates whether the user's input is relevant to the defined purpose or use case of the AI system. In RAG-based architectures, evaluates context-query alignment to detect retrieval failures before they propagate into poor-quality answers.

---

### Gibberish Detection

**Applies to:** Input, Output

Evaluates text coherence and linguistic structure to determine whether content is meaningful or nonsensical. On the input side, nonsensical prompts may indicate automated bot activity, fuzzing attacks, or encoding manipulation attempts.

---

### Hallucination Detection

**OWASP:** LLM09:2025 | **MITRE ATLAS:** AML.T0064
**Applies to:** Output

Assesses the factual accuracy of model outputs by comparing them against known or reference information. Tags responses as factual or hallucinated to identify when the model generates unsupported or incorrect claims.

---

### Refutation Alerting

**Applies to:** Output

Detects and tags instances where the model refuses to answer a request. Monitors trends in refusal frequency to help identify potential issues such as degradation in model performance or over-triggering of safety filters.

---

### Satisfactory Answer

**Applies to:** Output

Evaluates whether the model's response adequately addresses the user's question or request. Tags answers as satisfactory or unsatisfactory based on completeness, clarity, actionability, and appropriateness.

---

### Sensitive Features

**Applies to:** Input

Detects the presence of sensitive or protected attributes in user requests — such as age, gender, race, ethnicity. Tags requests containing these features to support bias detection and fairness assessments.

---

### LLM-as-a-Judge

**Applies to:** Input, Output

Uses a large language model to evaluate and tag content based on user-defined criteria. Enables flexible, customizable judgment for specialized use cases such as quality assessment, compliance checking, or behavioral analysis.
