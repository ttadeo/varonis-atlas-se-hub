# Atlas Issues — Shadow AI, Unprotected AI, and Issue Types Explained

Atlas automatically generates Issues to help security teams track and manage risks across AI systems. Understanding issue types is essential for triaging the Atlas dashboard after initial deployment.

## What Is a Shadow AI Issue?

A **Shadow AI issue** means Atlas has discovered an AI resource that has not been properly reviewed, approved, or assigned within the organization's AI governance process.

The two most likely causes of a Shadow AI issue are:

**Cause 1: Unreviewed resource** — A new AI resource was discovered by a scan (cloud account, code repository, or hosted service) but has not yet been reviewed by a team member. When a resource is first discovered, it is automatically assigned a status of "Unreviewed." All unreviewed resources generate a Shadow AI issue until they are explicitly approved or rejected by a reviewer.

**Cause 2: Unsanctioned (rejected) resource** — A resource was reviewed and deliberately marked as "Rejected" or unsanctioned. This means the security team has decided the resource should not be in use. Rejected resources remain flagged as Shadow AI issues until they are removed from the environment or re-evaluated.

A third cause is improper assignment: a resource was discovered and automatically added to the Default Project but was never reassigned to its correct project. Resources sitting in the Default Project without proper ownership are treated as governance gaps.

## What Is an Unprotected AI Issue?

An **Unprotected AI issue** is generated when an AI resource exists in inventory but is missing available protections within the Atlas platform. The most common example is an LLM Endpoint that has no AI Gateway attached to it. Atlas knows a Gateway is available and can protect that endpoint — if it hasn't been configured, the system flags it as unprotected.

## All Issue Types in Atlas

Issues are generated by every module in the system:

| Source | Issue Type | Example |
|--------|-----------|---------|
| **AI Inventory** | Shadow AI | New model discovered but not reviewed |
| **AI Inventory** | Unprotected AI | LLM Endpoint with no Gateway attached |
| **AI SPM** | Vulnerability | Python library with a known CVE |
| **AI SPM** | Misconfiguration | S3 bucket with AI models publicly accessible |
| **AI Gateway** | Policy Violation | Prompt blocked or flagged by a guardrail rule |
| **AI Compliance** | Compliance Gap | Framework control not satisfied |
| **AI Usage** | Usage Violation | Employee accessing unsanctioned AI service |

## How to Respond to a Shadow AI Issue

When a security analyst sees a Shadow AI issue:

1. **Navigate to AI Inventory** → Technologies tab
2. **Find the flagged resource** — it will show status "Unreviewed"
3. **Review the resource details** — what is it, who owns it, which project does it belong to?
4. **Take action**:
   - **Approve** — mark as sanctioned, assign to the correct project
   - **Reject** — mark as unsanctioned, initiate removal from the environment
5. **Assign to a project** — resources sitting in the Default Project should be moved to their correct project

Once all resources within a technology are reviewed, the Shadow AI issue for that technology resolves automatically.

## Issue Severity and Prioritization

Issues are assigned severity levels (Critical, High, Medium, Low). Shadow AI and Unprotected AI issues from Inventory are typically Medium severity — they represent governance gaps, not active attacks. Policy violation issues from the Gateway (blocked prompts, flagged guardrail triggers) can be higher severity depending on the rule that fired.

The AI 360 dashboard aggregates all open issues by severity, giving the security team a prioritized view of what needs attention first.
